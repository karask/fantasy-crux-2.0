# ADR-035: Allow generated diagrams in rules prose

## Status

Accepted

## Date

2026-10-15

## Context

Rules prose carried no images. ADR-001 kept components and raw HTML out of the
Markdown, and the content contract rejected every image so that art could not
drift into rules text. Chapter illustrations are placed by the layout instead.

Some rules are hard to follow as prose alone. The order of damage reduction,
the difference between Projected and Direct Harm, and how a Shaping's Magnitude
is built all span several paragraphs, and players asked the same questions
repeatedly: does armour stop a firebolt, can a shield block one, does Dodge
work against arrows. The rewrite for plain English (see
`docs/design/rules-style-guide.md`) needs pictures as well as shorter sentences.

## Decision

- Rules Markdown may embed **generated diagrams**, and nothing else, with
  standard image syntax on its own line:
  `![Alt text that states the rule.](../../../assets/diagrams/name.svg)`.
  The relative path also resolves when the Markdown is read on its own.
- Diagrams are SVG files generated by `scripts/build-diagrams.mjs` from shared
  primitives in `scripts/diagrams/`, so every diagram uses one palette, type
  scale, and shape language. `npm run diagrams:check` runs in `check:ci` and
  fails when a committed SVG is stale, missing, or has no generator.
- The build inlines each SVG inside a `<figure>` so it uses the site fonts. The
  SVG carries `role="img"` and the alt text as its accessible name. Diagrams
  contain no ids or `<defs>`, so several can share a chapter page. The figure is
  excluded from the search index; the prose remains the searchable rule.
- **The text is the rule.** Every fact in a diagram is also stated in prose or a
  table beside it. A diagram summarises; it never adds a rule.
- A table marked `{.verdicts}` tints answer cells that begin with Yes, No, All,
  Half, or None. The words still carry the meaning without colour.
- The content contract now rejects raw HTML and any image that is not a
  generated diagram with substantial alt text.

## Alternatives considered

### Keep rules text-only

This keeps the source simplest, but leaves the most-asked questions answered
only by careful reading across sections.

### Hand-drawn or painted images

Painted art suits the chapter illustrations, which ADR-014 governs. Rules
diagrams must change whenever a rule changes, stay exact, and remain legible on a
phone. Generated vector diagrams meet those needs; paintings do not.

### Components or raw HTML diagrams

HTML diagrams would reflow well, but they break ADR-001's portable Markdown and
would need a second implementation for the print handbook. SVG files work in
both.

## Consequences

- Diagrams are code-reviewed like rules and regenerate deterministically.
- The print handbook can reuse the same SVG files.
- Each diagram needs alt text written as a rule summary, and its facts must
  match the prose. Reviewers check both.
- ADR-001's ban on components and raw HTML in rules Markdown is unchanged.
